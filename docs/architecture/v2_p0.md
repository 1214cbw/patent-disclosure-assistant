# Patent Agent V2-P0 Architecture

## Architecture

```text
Source Materials
  -> Evidence Store
  -> TechnicalFact / GroundedStatement
  -> TechnicalUnderstandingResult
  -> Grounded Invention Candidate
  -> Evidence-aware Protection Strategy
  -> Grounded Disclosure / Claim Feature Set
  -> Claims Support Matrix
  -> Patent AST
  -> Existing Document Engine / OMML
  -> DOCX / Validation / Traceability
```

The V1 `PatentCase`, deterministic agents, Patent AST, Equation Engine, renderer and validators remain available. V2 is an additive pipeline and never permits an LLM to write OOXML.

## Data Flow

Ingestion creates stable `EvidenceChunk` records from source identity, logical position and normalized content hash. Retrieval selects a task-specific subset with a deterministic BM25-like scorer. Schema-bound LLM output passes Pydantic validation, Evidence ID validation, semantic overlap checks and business rules before a new case version is persisted.

Prior-art Evidence is stored under a separate `PRIOR_ART` scope and cannot support an invention-side `SOURCE_FACT`.

## Evidence Model

- `EvidenceChunk`: immutable source location and text.
- `TechnicalFact`: status, confidence and Evidence links; `SOURCE_FACT` without Evidence is invalid.
- `GroundedStatement`: shared evidence-aware statement model.
- `InventorAssertion`: accepted only when explicitly marked as user-confirmed.
- Priority: Source Evidence -> human-confirmed fact -> LLM inference.

## LLM Flow

`LLMProvider.generate_structured()` accepts a response model. `StructuredLLMService` adds prompt versions, finite retries, case-local cache and privacy-safe call metadata. Cache keys include provider, model, prompt version, input hash and schema. Full prompts are saved only when `PATENT_DEBUG_SAVE_LLM_PAYLOADS=true`.

Privacy modes:

- `disabled`: no provider calls; deterministic V1 and grounded dry-run fallback remain usable.
- `external-approved`: external transfer is explicitly approved and requires configured credentials.
- `local`: calls a local/intranet OpenAI-compatible endpoint; API key is optional.

Source text is tagged as untrusted material. Instructions embedded in uploaded files cannot replace system constraints. Model output is parsed as JSON and is never evaluated or executed.

## Claims Support

Claims are built in this order:

```text
Protection Strategy -> Supported Feature Pool -> Claim Tree -> Rendered Claim Text
```

The matrix links Claim -> Feature -> Disclosure Paragraph -> TechnicalFact -> Evidence. An unsupported mandatory independent-claim feature fails Gate 4. Broad and conservative drafts use the same supported pool.

## Security

- `.env`, `.env.*`, `private_cases/` and all runtime case data are ignored by Git.
- API keys are not written to reports, audits, cache keys or case JSON.
- Real-case dry-run requires an explicitly supplied materials path and stops before strategy, claims and Word.
- No paid/external smoke test runs unless `RUN_LLM_SMOKE_TESTS=1`.
- V1 case migration creates `case.v1.backup.json` before adding schema version 2.0.

## Quality Gates

1. Evidence Integrity
2. Technical Understanding
3. Invention Candidate
4. Claim Support
5. Traceability
6. Document Validation

Deterministic validation has veto authority over LLM semantic review.

## Failure Modes

- `LLM_DISABLED`
- `LLM_CONNECTION_FAILED`
- `LLM_SCHEMA_VALIDATION_FAILED`
- `INVALID_EVIDENCE_REFERENCE`
- `EVIDENCE_MISMATCH`
- `SOURCE_FACT_WITHOUT_EVIDENCE`
- `CLAIM_FEATURE_UNSUPPORTED`
- `TRACEABILITY_BROKEN`
- `INVENTOR_CONFIRMATION_REQUIRED`

Failures are logged with stage metadata and are never silently converted to plausible prose.
