# Patent Agent 用户使用手册

本手册面向发明人、研发人员和专利人员。日常操作在网页完成，不需要回到 Codex 或手工输入普通工程命令。

## 1. 如何启动

双击项目根目录的 `start_patent_agent.bat`。服务就绪后浏览器自动打开 `http://127.0.0.1:8765`。页面左上角应显示 `PRIVATE · LOCAL`。

## 2. 如何关闭

双击 `stop_patent_agent.bat`。不要在任务写入过程中强制结束 Python；若意外中断，按第 13 节恢复。

## 3. 如何创建案件

在“案件总览”创建案件。真实材料选择 PRIVATE Real Case；测试只能选择明确标记为 synthetic 的资料。案件 ID 建议使用 `REAL-主题-序号`，不要含路径字符。

## 4. 如何上传资料

在案件工作台选择文件并上传。只选择已获授权处理的文件；系统不会扫描同目录其他文件。支持 PDF、DOCX、PPTX、TXT、MD 和常见图片。References 只作为参考文献，不作为本发明事实。

## 5. 如何配置 DeepSeek

管理员在项目根目录 `.env` 填写 Provider、Base URL、API Key 和 Model。网页“设置与隐私”只显示是否配置，不显示 Key。真实案件调用外部模型前还必须具有案件级 `external-approved` 授权。

运行 A1 前先查看设置页；若状态不可用，停止真实分析并联系管理员。不要把 API Key 粘贴到案件材料、备注或聊天记录。

## 6. A1 怎么审

打开“技术理解审阅”，逐项核对事实：

- 接受：论文原文与系统理解一致。
- 编辑：保留原记录并写入人工修订。
- 拒绝：该理解错误或不应进入后续流程。

同时查看 Evidence ID、公式核查、术语和不确定问题。所有必审事实完成后才能批准 A1。批准前请再次确认：学术贡献不等于专利发明点，实验参数也不当然是必要技术特征。

## 7. 什么是 Evidence

Evidence 是带来源文件、页码、章节和稳定 ID 的原文逻辑块。`SOURCE_FACT` 必须指向真实 Evidence。`INFERRED` 是 Agent 推断，`UNVERIFIED` 是尚不能可靠确认的内容。点击 Evidence ID 可回到证据查看器核对上下文。

## 8. A2 怎么审

A2 审核发明候选。可接受、编辑、拒绝候选，并检查候选的技术问题、核心构思、必要/可选特征、技术效果和证据。不要仅因论文把某点列为 contribution 就批准它成为发明点。

## 9. B 怎么选

B 审核保护策略。重点判断必要特征、可选特征、术语宽窄、支持缺口和实施替代。Broad/Balanced/Conservative 只能在已有证据和人工确认事实内调整，不能为扩大范围虚构特征。

## 10. C 怎么审 Claims

逐项阅读 Claim 和 Feature Graph，再查看 Claims Support 与 Scope Review。确认每个必要特征有说明书与原始证据支持，避免把模型名、数据量、batch size、epoch、学习率或固定阈值无依据地锁入独立权利要求。

## 11. 如何生成 Word

C 批准后，按页面提示继续生成技术交底书和权利要求辅助草案。在“产物与导出”下载 DOCX、验证报告和可追溯报告。真实案件未经人工 Checkpoint 不会生成 Word。

## 12. Word 公式是什么

公式是 Microsoft Word 原生 OMML，可在 Word 中双击编辑，不是图片。系统保存原式、规范化 LaTeX、变量定义和 Evidence。遇到 `UNVERIFIED` 或解析警告时，以论文原式为准，禁止凭经验改写。

## 13. 如何恢复中断

重新双击启动脚本，打开“任务与恢复”，查看上次完成步骤和下一步，然后点击“恢复当前任务”。恢复不会自动批准 Checkpoint。命令行备用方式见 [RECOVERY](RECOVERY.md)。

## 14. 如何备份案件

关闭服务后，将 `workspace/private_cases/<CASE-ID>` 完整复制到经过授权的加密存储。不要提交 Git、云盘公开目录或邮件附件。恢复时保持目录结构不变。

## 15. 出错怎么办

1. 先记录页面错误码和步骤，不要复制 API Key。
2. 查看“任务与恢复”以及 `runtime/patent_agent_server.log`。
3. 用停止脚本安全停止，再重新启动。
4. 仍失败时按 [RECOVERY](RECOVERY.md) 收集 last known good commit、current phase 和 current failing test。

当前真实案件 `REAL-PAPER-001` 的下一步只有：人工审核 A1 v2，并确认 Publication Metadata。不要直接进入 A2。
